How this works. Your browser runs the project's heuristics (a JavaScript port of src/speedrun, checked against the Python version by tests/test_js_parity.py): precedence-feasible nearest neighbour and cheapest insertion (Session 1), improved by or-opt and 2-opt (Session 3) with random restarts (Session 10), for about 1.5 seconds. Days come from an exact shortest-path split of that order (Session 7) and are compared with the bin-packing lower bound ⌈Σ hours / H⌉ (Session 8). Crunch mode uses the profit-maximising tour heuristic (Session 9). Exact branch and bound is not run in the browser. Preset cards show the Python result for comparison. All hours and costs are estimates; see the report's sensitivity chapter.
