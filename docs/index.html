MBA Speedrun: personalised learning roadmaps as a Sequential Ordering Problem

Almost every IIMA student hits a catch-up crunch before end-terms or summer-placement prep. The core is taught as parallel courses for a cohort of ~400; a student catching up alone learns one topic at a time. This tool orders PGP core micro-topics so that every prerequisite comes first, subject switches and forgetting are kept low, and the result is split into days, using the logistics toolkit from Optimisation Methods in Logistics.

The data

266 micro-topics across all 37 first-year IIMA courses, 387 prerequisite links (358 required, 6 either-or, 23 recommended), about 382 hours of base study. 119 links are backed by the order of chapters or sessions in core textbooks and MIT syllabi, and 88% of the links that could be checked agree with that order. The other links, all hours and all values are the project's estimates.

Honest limits

  • Topic hours, values and the switching/synergy/forgetting parameters are estimates. The report's sensitivity chapter checks whether the conclusions survive ±25% changes (on the pilot they do).
  • Personalisation (skipping what you know) and treating shared concepts once are the biggest savings. On top of that, a domain-by-domain roadmap saves about 15–17% over going course by course, mostly by avoiding forgetting. That figure depends on the forgetting estimates, but stays positive under ±25% changes to every input.
  • The browser runs heuristics, not exact branch and bound, which is practical only up to about 20 topics. For large scopes it uses the two strongest constructions plus local search.

Extend it

Code, data and a walkthrough notebook per class concept are on GitHub. Ideas for the next group: real hours from a PGP2 survey, exam-weight values from the Acads committee, group study (several machines = several vehicles, a VRP), and time windows for exam dates.
